# Release 2026-11-13 — FB2: скорость, обложки, прогресс

Личный форк CrossPoint Reader (ветка `kimitest`, устройство X4 Pro).
Продолжение `release20261107.md`: три коммита (`8cccf194`, `ec44ec17`,
`23a13664`), проверено в эмуляторе и на реальном устройстве.
Тема релиза — конвертация FB2: скорость, обложки на home-экране,
видимый прогресс всех долгих операций и отзывчивость чтения.

---

## 1. Ускорение конвертации FB2

Файлы: `lib/Fb2/src/Fb2Converter.cpp`, `lib/Fb2/src/Fb2Passes.h`.

- **RawBinaryScanner.** Структурный проход expat останавливается на первом
  `<binary>` (`XML_StopParser`): всё релевантное для структуры лежит раньше,
  а реестр остальных картинок добирается сырым сканом хвоста файла — base64
  не содержит `<`, поэтому подстроковый поиск `<binary` безопасен. Мегабайты
  base64 больше не гоняются через XML-парсер.
- **Батчинг `emitEscaped`.** Текст эмитился посимвольно (миллионы вызовов
  `write(1)`); теперь экранирование копит 512-байтный стековый буфер и пишет
  прямо в zip, а глава открывается один раз на весь поток.
- **Буфер чтения 16→32 КБ**, перенесён со `static` на heap: память
  возвращается читалке сразу после конвертации, а не висит всю сессию.

**Нюанс:** raw-скан теоретически может поймать `<binary` внутри
XML-комментария в хвосте. Цена ложной записи — лишняя строка в манифесте
OPF; эмиссия ищет картинки по id, реальные записи не страдают.

## 2. Обложки FB2 на home-экране

Файлы: `src/activities/home/HomeActivity.cpp`, `src/util/BookProgress.cpp`.

Причина бага: home-экран и прогресс чтения открывали исходный `.fb2` как
ZIP (обложка и метаданные — ZIP-инструменты), а FB2-источник — XML. Теперь
все заинтересованные места проходят через `coverContentPath()`: для FB2
путь резолвится в синтетический EPUB через `Fb2::ensureEpub` (для уже
открытых книг — чистый кэш-хит, повторной конвертации нет). Заодно прогресс
чтения FB2 читается из кэша синтетика, а не «рядом с источником».

## 3. Исправления из ревью конвертера

- **UTF-8-безопасная обрезка nav-заголовков** (`utf8SafeLen`,
  `Fb2Passes.h`): обрезка по 96 байтам откатывается к границе кодпоинта.
  Раньше длинный кириллический заголовок резался посреди символа →
  невалидный UTF-8 в `nav.xhtml`, и строгий expat мог отвергнуть книгу
  целиком при чтении.
- **Контроль ошибок base64**: результат `b64.finish()` проверяется; битые
  или превысившие лимит размера картинки считаются (`brokenImages`) и громко
  логируются. Книга остаётся читабельной (запись в zip с валидным CRC),
  но проблема больше не молчит.

## 4. Типографика FB2

- **Диалоговое тире**: ведущее «— » в абзаце заменяется на «—&#160;» —
  NBSP не участвует в делёжке выключки, зазор после тире больше не
  растягивается. Детектор (`detectDialogDashPrefix`) придерживает первые
  байты абзаца, пока не решит, диалог это или нет (потолок 64 байта).
- **Стихи**: строкам `v` в эмиссии добавлен `text-align:left` — глобальная
  выключка больше не растягивает короткие строки поэзии на всю ширину.

## 5. Прогресс конвертации в UI

Колбэк `Fb2Converter::convert → Fb2::ensureEpub → EpubReaderActivity`:
фазы 0–10% (метаданные), 10–40% (структура), 40–100% (эмиссия). Проценты
маппятся из потребления байт файла и монотонны по построению — бар никогда
не идёт назад. Попап «Конвертация FB2» перерисовывается не чаще, чем шаг
≥2% или раз в 400 мс (плюс финальные 100%).

## 6. Отзывчивость чтения (фоновый билд секций)

Файлы: `src/activities/reader/EpubReaderActivity.{cpp,h}`.

Диагноз «зависания» после перелистывания: фоновый билд секции (у большой
FB2-главы — сотни страниц) шёл без пауз, и ввод обслуживался раз в тик.

- **Time-box тика**: `BACKGROUND_BUILD_TICK_BUDGET_MS = 100` — тик
  прерывается по дедлайну или нажатию; латентность ввода ограничена одним
  тиком.
- **Полоска прогресса** 4 px по верхней кромке: показывается для секций
  ≥40 страниц, шаг 5%, монотонна в пределах секции, корректно переживает
  loan фреймбуфера. Работает для всех форматов, не только FB2.
