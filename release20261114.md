# Release 2026-11-14 — UX-итерация, буквица, размеры файлов

Личный форк CrossPoint Reader (ветка `kimitest`, устройство X4 Pro).
Продолжение `release20261113.md`: три коммита (`f8ef4947`, `6131600d`,
`ea6a79ee`), проверено в эмуляторе и на реальном устройстве.
Тема релиза — пожелания после живого тестирования: FB2 без лишних
конвертаций, корректные переносы у буквицы, размеры файлов в браузере.

---

## 1. UX-итерация 2026-11-13 (`f8ef4947`)

Закрывает раздел 1a `future.md` целиком.

- **FB2 исключён из библиотечного индекса** (`LibraryBuilder.cpp`): полка
  с тысячами FB2 перестала тратить минуты на индексацию. Побочный эффект:
  cover-grid home строится из индекса, поэтому FB2 там не появляются
  (Recents остаются).
- **`Fb2::cachedEpub`** (`Fb2.cpp/.h`): лукап кэша синтетического EPUB без
  конвертации. `coverContentPath()` (`HomeActivity.cpp`) и
  `loadBookProgress` (`BookProgress.cpp`) используют его вместо
  `ensureEpub` — после Clear Cache home-экран больше не фризится на
  пакетной конвертации recents; обложка и прогресс появляются после
  первого открытия книги.
- **Действие по тапу на слово** (`selectionDefaultAction` в настройках,
  `ClipSelectionActivity.cpp`): «спросить / словарь / вырезка / закладка» —
  тап выполняет выбранное действие сразу, без тапа по панели.
  Long-press-выделение фраз всегда показывает панель. +1 строка перевода
  (ru/en).
- **Файловый браузер возобновляется** (`browserLastPath`/`browserLastEntry`
  в `CrossPointState`): вход через Home открывает папку и выделение
  последней открытой книги. Явные пути (возврат из просмотрщика картинок)
  не затрагиваются.

## 2. Переносы у буквицы (`6131600d`)

Файлы: `lib/Epub/Epub/ParsedText.{cpp,h}`, `lib/Epub/Epub/Section.cpp`,
`docs/file-formats.md`, тесты `test/chapter_html_slim_parser/`.

Симптом: у картинки-буквицы (первая буква главы на 4 строки) переносы в
строках после обтекания расставлялись по узкой ширине (экран минус
буквица), хотя строки уже полноширинные.

Корень: `ParsedText::computeHyphenatedLineBreaks` на первом проходе
(узкая колонка, `maxLines`) материализовал сплиты для всего абзаца —
`hyphenateWordAtIndex` печатает дефис прямо в префикс слова. После
извлечения `maxLines` строк остаточные узкие разрезы доставались
полноширинному второму проходу.

Фикс: параметр `maxBreaks` — цикл останавливается, набрав нужное число
строк, не трогая хвост абзаца; `lineCount`/`endIsKnown` корректируются
через `stoppedEarly`. Формат кэша секций бампнут `SECTION_FILE_VERSION`
67 → 68 (запись в `docs/file-formats.md`): старые кэши с «запечёнными»
узкими разрезами пересобираются сами, ручная очистка не нужна — проверено
на устройстве.

Тесты: `ChapterHtmlSlimParserTest` 119/119, включая новый
`DropCapHyphenation.TailAfterNarrowPhaseUsesFullWidth` (падает без фикса,
зелёный с ним); в `ParserLinkStubs.cpp` добавлен opt-in крюк
`gTestHyphenationFallbackEnabled`, чтобы стаб Hyphenator мог возвращать
реальные точки переноса.

## 3. Размеры файлов в браузере (`ea6a79ee`)

Файлы: `src/activities/home/FileBrowserActivity.{cpp,h}`.

Было: имя без расширения слева, расширение — правой колонкой.
Стало: слева полное имя (`book.fb2`), справа размер в человеческом виде
(`512 B`, `245 KB`, `3.4 MB`, `12 MB`); у папок правая колонка пуста.

- Список — `std::vector<FileEntry> { name, sizeBytes }`; сортировка
  прежняя (папки первыми + `naturalLess`), компаратор по `.name`.
- Размер читается при листинге через `HalFile::fileSize()` — данные уже
  есть в прочитанной записи каталога FAT, **дополнительных обращений
  к SD нет**; на 1000 файлов +8 КБ RAM, листинг не замедляется.
- Единицы латинские, без строк перевода; десятые МБ считаются
  целочисленно (без float-printf).
- Работает и в режиме выбора прошивки (`.bin`).
